# M1–M4 阶段交付报告（2026-08-27）

## 背景与目标

项目面向贪心题学习场景：题面+C++代码，经 Hy3 静态诊断输出算法概述、首次错误、
代码位置、反例与完整解法。采用 C++17、原生网页和既有 TokenHub transport，
没有迁移框架、连接 OJ 或恢复通用 CandidateRunner。

本报告区分程序验证、固定测试结果、模型效果与真实人工结论。最新三条开发试跑均未通过输出契约，正式效果与人工结论仍未完成；见[M3试跑记录](journal/m3-development-pilot.md)。

## 设计与实现

网页 v2 保持代码优先和安全文本渲染；独立离线 evaluation-v1 在同一诊断响应中增加结构化完整代码。
位置校验检查 LF 行范围、精确片段和逻辑步骤引用；它不证明模型自然语言诊断正确。
输入 allowlist 排除参考答案、gold、难度和集合标签，代码与可选说明均为待分析数据。

离线答案路径仅在批准的 Linux/WSL bubblewrap 中运行受控材料；无网络、清空环境，
不挂载用户目录/密钥，以 argv 编译执行并限制时间、输出、内存和进程。
参考输出由不同算法的小规模穷举/递归/DP 再核对；不是让同一参考程序自证。

用量保护为追加式预算账本：调用前持久化保守上界，usage 后对账，
未知消耗继续占额，重复/中断请求不重发。详情和命令见 [评测契约](evaluation-v1.md)。

## 有效性限制

固定测试小，不能验证大规模性能或所有边界。过程gold尚无真人确认，
类别划分与难度具有主观性；复杂度问题的判定依赖分析而非小测试超时。
原始网页v2未在本轮真实模型下验证，严格schema可能拒绝有价值但格式不符的响应。
精确行范围匹配也不能代替根因语义审查。没有校准置信度、没有泛化或提升声明。
隔离依赖OS内核与bubblewrap，不是对恶意任意代码的完整强沙箱。
当前仓库未发现顶层LICENSE；作者需决定项目许可，本轮未重授权第三方材料。
